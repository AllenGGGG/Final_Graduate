# 面向低空智联的多模态网络切片技术：第一部分收敛设计

状态：设计及原生接口验证版，尚无本版正式训练或测试结论。旧档位版的成绩不能作为本版成绩。

## 1. 研究范围

论文题目和三个研究点保持不变。本次只实现第一部分“智能分配”：搭建低空背景，在共享物理网络上运行三种网络机制，在每个切片请求到达时决定准入、模态和功能位置。资源预测、运行期QoS控制后续使用同一个环境及日志，本次不加入训练目标。

网络机制多模态指IP、受限EID-RLOC、NDN，不是视觉/语音多模态。参照HRL-ACRA关于准入与资源嵌入联合决策的思路，但小规模候选集直接用一个Masked Double-DQN评分，不照搬分层RL、GNN或序列解码器。参考：https://arxiv.org/abs/2406.17334 。CLARA区分瞬时资源约束和累计服务约束；本版只实现资源合法性掩码，SLA通过真实交付测量，不声称实现CLARA或其约束保证。参考：https://arxiv.org/abs/2111.08397 。

## 2. 低空环境

采用已有allocation_final场景：任务平台—双边缘—双AP—12架无人机，固定高度80m，其中4架巡检、8架驻留，巡检速度5/8/11m/s。两个AP同信道，802.11a固定24Mbps，LogDistance指数2.5，有限覆盖距离120m，发射功率20dBm。关联、竞争和交付由ns-3运行，定位及轨迹只向控制器公开当前/历史观测。

保留现有缩比容量：回源每链路1Mbps，跨边缘0.5Mbps，AP有线接入2Mbps，每链路2ms。共同空口准入预算0.65秒/秒；每边缘映射8项、映射缓存8项、地图缓存16KB。17维账本由10个有线方向、共享空口、两边缘各自的映射/映射缓存/内容缓存组成。账本是准入预约，不能当作逐切片带宽保证。

先固定物理参数，用请求数量32/64/96的开发实验检查轻、中、重负载，记录资源占用、排队和拒绝原因。容量若需调整，应由瓶颈计数器和任务需求解释，并同时作用于所有方法；禁止查看正式测试后修改环境，也不以RL必须获胜选择容量。

## 3. 多模态与业务

| 业务 | 同一业务允许的机制 | 业务合同 |
|---|---|---|
| 遥测 | IP上行 | 1000B，周期20/40/80ms，期限200ms，至少95%按时 |
| 命令 | IP或EID-RLOC下行 | 512B，周期300ms，期限600ms，至少95%按时 |
| 地图 | IP下发或NDN获取 | 每对象4/8个1000B块，周期2s，期限800ms，全部块按时 |

请求声明租户、业务、端点、生命周期和SLA，不预先指定模态。持续3/5/7s，请求在2—18s到达；业务比例35%遥测、25%命令、40%地图。不同机制使用相同有效载荷、产生时间和SLA；NDN统计Interest、Data与回源开销，ID统计注册、查询和封装。

EID-RLOC是简化映射机制，不能称完整LISP；现有IP下行绑定初始定位，不包含连接迁移，因此移动实验不能据此声称ID优于所有IP移动方案。仿真平台用于小规模受控实验，不代表一般低空实测网络。

## 4. 智能分配

每次请求到达时，选择拒绝，或从合法候选集中选择“模态、接入边缘、映射服务器/内容缓存位置”。动作数组保留11槽，但不是每类业务都有10个接纳选项：遥测最多2个，命令最多6个，地图最多6个；其余槽位由掩码关闭。候选由业务语义、端点数量、拓扑及资源可行性生成。

不再提供0.9/1.1/1.4资源档位，不放大/缩小预约，不超订，不使用对偶乘子。原生业务按合同产生并进入真实链路竞争，不通过人为源端限速制造档位优劣。

状态包含当前请求、当前资源占用、端点位置/历史速度/关联、已发生的交付计数，以及候选配置的资源与位置特征。主版本关闭未来预约日历输入以控制范围；可行性检查仍检查已签合同的占用时间。未来请求和私有轨迹不进入状态。

算法固定Masked Double-DQN：一个共享候选编码网络为拒绝和每个候选输出标量Q值；探索、执行和Double-Q自举均遵守掩码。复用现有多步回放，宽度96、学习率1e-4、batch128、每4次决策更新一次；不追加辅助头、模仿学习或其他算法竞赛。

奖励是本次推进后新结算且实际满足SLA的请求数，gamma=1。整个回合奖励总和必须等于实际成功合同数。拒绝计零分且仍在到达分母中；不奖励单纯接纳，不用业务权重掩盖分业务表现。

学习的长期取舍是：本次接纳占用资源至合同结束，可能减少后续接纳机会；不同部署改变共享路径、映射占用、内容复用和实际交付。此机制允许长期优化，但是否存在可观的RL增益必须由开发实验确认，不能从“存在多个动作”直接推出。

## 5. 实现与验收顺序

1. 原生执行验证：分别运行三类业务，核对业务方向、映射注册、缓存复用、移动关联、逐包截止时间和最终状态释放。
2. 分配接口验证：固定11槽，排除档位字段，掩码只检查已知合法性；奖励与逐包SLA计数一致。用64步原生训练确认梯度更新与模型重载，只证明链路可运行，不报告RL性能。
3. 开发诊断：同场景对比部署选择，检查实际字节、交付和剩余接纳能力是否变化。若只是低档必失败/高档必成功，或不同部署在实际交付上等价，继续修正建模，不启动大规模训练。单纯“乐观上界较高”不能替代此检查。
4. 正式训练：5个初始化11/23/37/53/71，各32768次决策，保存8192/16384/32768检查点。验证92000—92029、负载48/80，按验证SLA成功率选择每个初始化的检查点，保留全部初始化。
5. 正式测试：锁定模型及协议后使用93000—93029、负载48/80。规则和RL复用完全相同的业务与无线种子。保存输入、决策、逐包事件和独立审计。测试结果不能反向选择超参数。

主基线固定Greedy，取当前合法候选中归一化资源占用最少的配置；Nearest取当前关联最近边缘，First-Fit取第一个合法配置。所有方法都使用相同合同和资源约束。若补充价格规则，保留其真实成绩，不按强弱删除。

主指标为实际SLA成功请求数/全部到达请求数，同时报告接纳率、接纳后违约率、分业务成功率、强制/主动拒绝、实际链路字节、空口发射时间及决策时间。正式报告按场景配对比较，区分场景与初始化重复。
