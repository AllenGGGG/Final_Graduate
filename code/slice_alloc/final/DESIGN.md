# 面向低空智联的多模态网络切片技术

项目只围绕一条主线：**搭建低空背景 → 实现多模态网络 → 完成网络切片智能分配**。这里“多模态”指IP、EID-RLOC和NDN三种网络机制。

## 1. 低空背景

用ns-3搭建12架无人机、2个AP、2个互连边缘和任务平台。无人机高度80米，其中4架巡检、8架驻留；移动、关联、空口竞争、重传及实际收发由仿真器产生。三种模态共享这些无线与有线设备。

这是低空巡检的简化实验场景。固定高度、802.11a固定速率、有限覆盖范围及缩比链路容量是实验条件，结果的适用范围由这些条件限定。

## 2. 多模态网络实现

| 业务 | 允许的承载 | 配置的作用 |
|---|---|---|
| 遥测 | IP上行 | 无人机向任务平台发送数据，选择承载边缘与路径 |
| 命令 | IP或EID-RLOC下行 | 选择边缘；采用EID-RLOC时选择映射服务位置 |
| 地图 | IP下发或NDN获取 | 选择边缘；采用NDN时选择是否使用边缘缓存及缓存位置 |

IP使用原生协议栈，EID-RLOC实现受限的注册、查询、更新和封装，NDN使用原生NFD转发与缓存。EID-RLOC部分属于简化实现。相同业务在可选模态下保持相同有效载荷、产生时刻、接收端及SLA，协议开销由实际运行产生。

实现见[原生场景](../execution/allocation_final_scenario.cc)，业务兼容关系和控制器见[分配环境](../allocation_final.py)。

## 3. 网络切片智能分配

一个请求给出业务类型、端点、开始/结束时间、数据量或周期、时延期限与最低按时率。控制器在请求到达时作一次初始分配：

**切片请求 → 生成可行配置 → RL选择 → 配置执行与资源预约 → 实际交付核验**

可选决策是拒绝，或者一个完整配置：承载模态、边缘位置，以及该模态需要的映射/缓存位置。业务合同和所选路径共同决定预约量；当前实现的资源分配包括承载选择、功能位置和相应资源预约。

选择依据是当前请求、已签切片的资源占用与释放时间、已观测的位置和关联，以及已发生的交付计数。资源账本覆盖有线方向、共享空口、映射状态和缓存，共17维；控制器不读取未来到达与私有未来轨迹。

先用可行性掩码排除业务不兼容或预约超额的配置，再由RL在合法配置中选择。配置发送给原生执行器，落实承载路径、映射或缓存；切片结束后释放预约。奖励依据实际满足SLA的请求数，拒绝计失败。预约可行与真实SLA是否满足分别核对，账本预约本身不构成逐切片带宽或时延保证。

验证时重读逐包事件，按业务合同重建按时率，检查遥测方向和资源事务；保存模型还要通过重载及事件重放。这使“怎么选择、怎么分配、最终有没有交付成功”能够逐项追溯。

本轮由验证集选定Masked Double-DQN作为最终分配器。它以共享候选编码估计各合法配置的回报，再选择一个完整配置；PPO、QR-DQN和A2C的比较作为选型依据，项目主线保持上述三层。主要对照保留Greedy，并配合First-Fit、近边优先和固定配额；完整结果及选定方法见[最终结果](README.md)。

详细参数与冻结方式见[实现规格](../ALLOCATION_FINAL.md)。
